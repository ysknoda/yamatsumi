# yamatsumi

> **Alpha release.** This project is under active development.
> Interfaces, behavior, and output formats may change without notice
> between releases, and it has not yet been broadly tested. Do not
> rely on it for production use.

CI-NEB (Climbing Image Nudged Elastic Band) transition-state search driven
by VASP.

Given two relaxed endpoint structures (`POSCAR_init`, `POSCAR_final`),
`yamatsumi` interpolates a chain of intermediate images, runs VASP single-point
calculations on each image, computes NEB spring forces and an improved
tangent (Henkelman & Jonsson, *J. Chem. Phys.* 113, 9901 (2000)), climbs the
highest-energy image toward the saddle point, and iterates to convergence
with a choice of optimiser (steepest-descent / Quick-Min / FIRE). On
convergence it verifies the transition state with a finite-difference
phonon calculation (exactly one imaginary frequency) and plots the energy
profile along the reaction path.

## Installation

```bash
pip install -e .            # core install (numpy only)
pip install -e ".[all]"     # + mpi4py, numba, matplotlib, scipy, pytest
```

Individual extras: `.[mpi]`, `.[jit]`, `.[plot]`, `.[test]`. Everything
outside of `numpy` degrades gracefully when absent (matplotlib -> plotting
is skipped with a warning; mpi4py/numba -> falls back to serial/pure-numpy
execution).

## Quick start

```bash
# Full pipeline (init + neb), single machine:
python -m yamatsumi --phase all --num-images 5 --vasp-cmd "vasp_std"

# Same, using the installed console script:
yamatsumi --phase all --num-images 5 --vasp-cmd "vasp_std"

# Per-image VASP itself run with MPI, single yamatsumi driver process:
yamatsumi --phase all --vasp-cmd "mpirun -np 4 vasp_std"

# Parallelise NEB images across a local thread pool (no MPI needed):
yamatsumi --phase all --local-workers 4

# Parallelise NEB images across MPI ranks (one rank per image):
mpirun -n 7 python -m yamatsumi --phase all --num-images 5

# Re-plot from an existing run:
yamatsumi --phase plot --work-dir NEB_run
```

Run `yamatsumi -h` for the full option reference. `CopyDir` must contain
`INCAR`, `KPOINTS`, and `POTCAR` (any `POSCAR` placed there is ignored --
image POSCARs are always generated by `yamatsumi` itself). `CopyDir/INCAR`
must also keep VASP as a single-point evaluator (`NSW=0`, `IBRION=-1`, the
VASP defaults if the tags are absent) -- `yamatsumi` checks this at startup
and stops with an explanatory error otherwise, since it drives atom
positions externally; pass `--allow-vasp-relaxation` to skip the check for
an intentionally non-standard setup.

## Reaction-path analysis features

```bash
# Better initial path guess for multi-atom systems (Image Dependent Pair
# Potential, Smidstrup et al. 2014) instead of plain linear interpolation:
yamatsumi --phase init --path-interpolation idpp

# Order-of-magnitude Arrhenius rate estimate alongside the barrier:
yamatsumi --phase all --rate-estimate arrhenius --temperature 300
```

On convergence, if the phonon verification finds exactly one imaginary
frequency, `yamatsumi` also parses that mode's eigenvector and reports its
alignment with the NEB tangent at the climbing image
(`Eigenvector-tangent alignment` in `yamatsumi_result.txt`, 1.0 = the
saddle's unstable direction exactly matches the intended reaction
coordinate) -- a diagnostic for whether the transition state found is the
one the path was actually aiming for, not just "some" saddle point.

## VASP execution robustness

- A VASP run is only accepted if it exits 0 **and** its log contains no
  known fatal-error banner (some VASP failures do not set a nonzero exit
  code).
- `--vasp-timeout SEC` kills and fails a single VASP invocation that runs
  longer than `SEC` seconds (default: unbounded, the previous behaviour).
- A stale `OUTCAR`/`CONTCAR` left behind by a crashed or interrupted run is
  always removed before the directory is reused, so it can never be
  silently mistaken for a fresh result.

## Try it without VASP

`examples/muller_brown_demo/` runs the full pipeline against a mock VASP
executable that evaluates the analytic Muller-Brown potential surface
instead of calling real VASP -- no license, POTCAR, or DFT calculation
required. See `examples/muller_brown_demo/README.md`.

## Package layout

```
yamatsumi/
  poscar.py, geometry.py       POSCAR I/O and coordinate transforms
  outcar.py                    OUTCAR parsers (energy, forces, frequencies, eigenvectors)
  interpolate.py                MIC linear and IDPP image interpolation
  neb_forces.py, optimizers.py   NEB force engine and SD/Quick-Min/FIRE steppers
  constraints.py                 Selective Dynamics (fixed-atom) mask helpers
  parallel.py, vasp_runner.py     mpi4py / thread-pool / serial VASP dispatch
  numba_shims.py                  optional numba JIT with a no-op fallback
  phonon.py                        TS verification + eigenvector-tangent alignment
  kinetics.py                       activation barriers, Arrhenius rate estimate
  plotting.py                       energy-profile plotting
  phases/                           init / neb / plot workflow phases
  cli.py                             argument parser and entry point
tests/                                pytest suite, incl. a mock-VASP fixture
examples/muller_brown_demo/            self-contained no-VASP-required demo
docs/real_vasp_validation.md            manual validation procedure with real VASP
```

## Notes on this version

Earlier single-file versions of this script had three correctness issues,
fixed here:

- Non-orthogonal lattices (hexagonal, monoclinic, triclinic, or any sheared
  cell) previously had their Cartesian<->Direct coordinate conversion
  silently corrupted on every optimiser step. Fixed; regression-tested in
  `tests/test_geometry.py`.
- The POSCAR "universal scaling factor" (including VASP's negative-scale
  "target cell volume" convention) was not applied consistently; it is now
  resolved and baked into the lattice once at parse time. Regression-tested
  in `tests/test_poscar.py`.
- Selective Dynamics (per-atom fixed/free flags, e.g. a frozen slab bottom
  layer) were parsed but then silently discarded. They are now preserved
  through read/write and enforced throughout the NEB force engine and every
  optimiser. Regression-tested in `tests/test_poscar.py` /
  `tests/test_neb_forces.py` / `tests/test_optimizers.py`.

A later code-quality audit found and fixed two further issues:

- **`--optimizer quickmin`** applied its adaptive `step_size / max_force`
  scale factor to the position update twice (once implicitly, via the
  velocity it had already been folded into; once again explicitly). This was
  invisible for O(1) eV/Ang forces but caused the displacement to blow up
  well past the `--step-size` cap as the force on an image shrank towards
  convergence (e.g. a 1e-4 eV/Ang residual force with the default
  `--step-size 0.05` produced a 25 Ang single-step displacement -- 500x the
  intended cap). Fixed; regression-tested in `tests/test_optimizers.py`.
  Neither the Muller-Brown/double-well integration tests nor the demo use
  `quickmin` (both use `fire`), which is why this was not caught earlier --
  any past run using `--optimizer quickmin` should be re-checked.
- `--rate-estimate arrhenius` with a non-positive `--temperature` (or
  `--attempt-freq`) raised an uninformative `ZeroDivisionError` deep inside
  `finalize()`, i.e. only after a full (potentially hours-long) NEB run had
  already converged. Both are now validated eagerly at the start of Phase 2,
  before the optimisation loop runs. Regression-tested in
  `tests/test_kinetics.py` / `tests/test_neb_phase.py`.

A second audit pass added the following, all regression-tested:

- **Resuming a run that had used up every iteration** (`--phase neb --resume`
  after a previous run hit `--max-iter` without converging -- exactly the
  situation `--resume` exists for) crashed with a bare `IndexError`, because
  the iteration range came out empty and the final report had no energies to
  print. It now stops with a message saying so and telling you to raise
  `--max-iter`.
- **Numeric CLI values are validated up front.** `--log-interval 0` used to
  crash with `ZeroDivisionError` on the first iteration; a non-positive
  `--step-size` silently either froze the path (0) or drove it *uphill*
  (negative); a negative `--spring-const` silently pushed images apart along
  the path; `--vasp-timeout 0` made every VASP call time out instantly. These
  and the other numeric flags are now rejected with an explanatory error
  before any phase starts. (`--spring-const 0` remains allowed -- it is a
  legitimate "no spring" variant.)
- **`--path-interpolation idpp` with a duplicated atom** in an endpoint
  POSCAR produced NaN coordinates silently (IDPP weights atom pairs by
  `1/d^4`, so a zero separation makes the weight infinite and NaN then
  propagates through the relaxation without raising). It now reports which
  two atoms coincide. Plain linear interpolation never used interatomic
  distances and was unaffected.

## Testing

```bash
pytest tests/                    # fast suite (no real VASP or MPI needed)
pytest tests/ -m "not slow"      # skip the slower Muller-Brown benchmark
```

`tests/test_mpi_integration.py` requires a working `mpirun`/`mpiexec` +
mpi4py runtime and is skipped automatically when one isn't available (this
is normal on a single workstation without MPI installed). See
`docs/real_vasp_validation.md` for a manual validation procedure against
real VASP calculations.
